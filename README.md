# AdaptiveML DSS

**AdaptiveML DSS** — это платформа автоматизированного машинного обучения и поддержки принятия решений для табличных данных.

Система позволяет загружать пользовательские датасеты, автоматически обучать модели на базе **LightAutoML**, выполнять предсказания на новых данных, объяснять результаты с помощью **SHAP** и формировать рекомендации через слой правил на **Experta**.

## Идея проекта

Проект строится вокруг конвейера:

**dataset -> AutoML model -> prediction -> explanation -> decision rules -> recommendation**

То есть система не ограничивается только обучением модели. Она должна:

- принять пользовательский табличный датасет;
- автоматически построить ML-модель;
- сделать прогноз для новых записей;
- объяснить, почему был получен именно такой прогноз;
- выдать понятную прикладную рекомендацию в рамках СППР;
- переобучить модель при поступлении новых размеченных данных.

## Ключевые возможности

- загрузка и валидация табличных датасетов;
- автоматическое обучение моделей с использованием **LightAutoML**;
- предсказание на новых данных;
- локальное объяснение предсказаний через **SHAP**;
- генерация рекомендаций через экспертные правила **Experta**;
- хранение версий датасетов и моделей;
- история моделей проекта и ручное переключение активной версии;
- сохранение holdout-предсказаний и training artifacts вместе с версией модели;
- контролируемое переобучение на новых данных;
- интерактивный график прогноза с масштабированием, прокруткой и выбором горизонта ползунком;
- мониторинг качества и drift-сценариев.

## Почему именно этот стек

### LightAutoML
Используется как AutoML-ядро системы. Отвечает за:
- автоматическую подготовку табличных данных;
- обучение модели;
- оценку качества;
- выдачу предсказаний.

### SHAP
Используется как explainability-слой. Отвечает за:
- объяснение конкретного предсказания;
- определение факторов, которые сильнее всего повлияли на результат;
- формирование интерпретируемого контекста для СППР.

### Experta
Используется как rule engine. Отвечает за:
- обработку фактов;
- применение экспертных правил;
- генерацию итоговой рекомендации на основе прогноза и объяснения.

## Как работает система

### 1. Обучение модели
Пользователь загружает исходный датасет, выбирает целевую переменную и запускает обучение.  
Система валидирует данные, определяет тип задачи и передает датасет в **LightAutoML**.

Результатом становятся:
- обученная модель;
- метрики качества;
- версия датасета;
- версия модели;
- holdout-предсказания на тестовом split;
- training artifacts и diagnostics, сохранённые в registry.

### 2. Предсказание
Пользователь загружает новые записи без target-колонки.  
Система проверяет совместимость схемы, загружает активную модель и выполняет предсказание.

Результатом становятся:
- прогноз;
- вероятность / confidence;
- технический результат инференса.

### 3. Объяснение результата
После получения прогноза вызывается **SHAP**.

SHAP определяет:
- какие признаки внесли наибольший вклад в прогноз;
- какие признаки увеличили риск / значение;
- какие признаки, наоборот, снизили итоговый результат.

Результат этого этапа — не просто список чисел, а интерпретируемый набор факторов.

### 4. Генерация рекомендации
Выход SHAP преобразуется в факты для **Experta**.

Например:
- `risk_level = high`
- `temperature_impact = strong_positive`
- `vibration_impact = medium_positive`
- `pressure_impact = weak_negative`

На основе этих фактов rule engine выбирает сценарий решения и формирует рекомендацию.

Например:
- снизить нагрузку;
- проверить систему охлаждения;
- провести диагностику узла;
- передать случай на ручную проверку.

### 5. Переобучение
Если пользователь загружает новые размеченные данные, система:
- сохраняет их как новую версию датасета;
- анализирует пригодность для переобучения;
- запускает повторное обучение;
- сравнивает новую модель с текущей;
- публикует новую `champion`-версию только при улучшении качества.

## Архитектура

Система включает следующие основные модули:

### Веб-интерфейс / клиент
Интерфейс пользователя для:
- создания проекта;
- просмотра истории моделей проекта;
- загрузки данных;
- запуска обучения;
- переключения активной модели;
- просмотра графика истории и прогноза;
- просмотра рекомендаций.

### API Gateway / ядро backend
Центральный backend, который:
- управляет проектами;
- маршрутизирует запросы;
- запускает training/prediction jobs;
- связывает все модули платформы.

### Прием и валидация данных
Модуль приема и проверки данных:
- проверка формата;
- определение типов колонок;
- поиск пропусков и дубликатов;
- контроль совместимости схемы;
- подготовка датасета к обучению или инференсу.

### Реестр датасетов
Хранит:
- версии датасетов;
- схемы данных;
- источники загрузки;
- статус наборов данных.

### AutoML-движок
Построен на **LightAutoML**.  
Отвечает за:
- автоматическое обучение моделей;
- выбор лучшего pipeline;
- оценку качества;
- сериализацию модели.

### Реестр моделей
Хранит:
- версии моделей;
- метрики;
- статус модели;
- связь модели с конкретной версией датасета;
- holdout-предсказания;
- training artifacts.

Статусы модели:
- `candidate`
- `champion`
- `archived`

### Сервис предсказаний
Отвечает за:
- загрузку активной модели;
- проверку входных данных;
- выполнение предсказания.

### Сервис объяснений
Отвечает за:
- запуск SHAP;
- получение локального объяснения предсказания;
- выделение top factors;
- подготовку explainability-контекста.

### Сервис поддержки решений
Отвечает за:
- преобразование предсказания и SHAP-значений в факты;
- запуск rule engine;
- сборку итоговой рекомендации.

### Машина правил
Реализуется на **Experta**.  
Содержит:
- правила;
- шаблоны решений;
- сценарии действий;
- приоритеты рекомендаций.

### Мониторинг и переобучение
Отвечает за:
- мониторинг drift;
- накопление новых данных;
- запуск контролируемого переобучения;
- сравнение новой модели с текущей.

## Быстрый старт
```bash
git clone <repo-url>
cd adaptiveml-dss
scripts/setup_full_env.sh python3.13
source .venv/bin/activate
uvicorn backend.main:app --reload
```

Для Windows:

```powershell
scripts\setup_full_env.cmd
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

После запуска API фронтенд доступен на:

```text
http://localhost:8000/app/
```

Основные страницы UI:

- `/app/index.html` — проекты;
- `/app/training.html` — обучение и переобучение;
- `/app/models.html?project_id=<id>` — история моделей и переключение active/champion;
- `/app/graph.html?project_id=<id>` — график истории и прогноза.
